# F2 — plan del prototipo de ruta caliente (2026-11-13)

## Objetivo

Demostrar con medición reproducible que el pipeline Go reproduce las decisiones
del oráculo TS y no empeora la latencia. Si el gate F2 falla, **no se sigue** a
F3: se corrige el diseño.

## Material disponible

- Corpus congelado `parity/fixtures/replay/2026-11-12/`: 10 eventos, 4
  escenarios, 14 pasos y 18 decisiones con `stateDigest`.
- Cargador Go validado: `services/trading-core/internal/replay/corpus`.
- Comando de diagnóstico:

```bash
cd services/trading-core
go run ./cmd/replay-probe --corpus ../../parity/fixtures/replay/2026-11-12
```

```text
replay-probe: corpus=2026-11-12 events=10 scenarios=4 steps=14 decisions=18
```

- Dominio puro portado con 159/159 goldens L1.
- Fake QvaPay de F0 y contratos K1–K14.
- `market.ingest` reproducido en Go: 4/4 resultados del corpus (dedupe, feed y
  observación) en `internal/replay/marketsession`.

## Alcance del prototipo

1. **Sesión replay**: cargar el corpus, reloj virtual, SQLite temporal (o
   Postgres de desarrollo) y gateway guionizado. Sin red real, sin Telegram,
   sin panel, sin mutaciones reales.
2. **Pipeline**: evento → dedupe → observación → oportunidad → riesgo →
   liquidez → presupuesto → reserva → `mutation_intent` → fake QvaPay →
   conciliación.
3. **Comparador**: decisión, resultado y `stateDigest` contra
   `decisions.ndjson`; el orden y los importes deben ser idénticos.
4. **Recuperación**: kill -9 en puntos medios, sin `apply` duplicado y con
   intents resueltos o `uncertain` explícitos.
5. **Benchmark**: mismo corpus y máquina para TS y Go.

## Mediciones y gate

| Métrica | Objetivo |
| --- | --- |
| Decisiones idénticas | 100 % del corpus; diferencias solo documentadas |
| p50/p95/p99 recepción→despacho | Registrar; p99 objetivo < 10 ms local |
| RSS/CPU en reposo y bajo replay | Registrar TS vs Go |
| Recuperación tras kill -9 | 0 applies duplicados, 100 % intents resueltos |
| 429/timeout/ambiguo | Mismo comportamiento que el oráculo |

Informe final: `docs/migration/2026-xx-f2-prototype-report.md` con números,
limitaciones y decisión explícita (continuar, ajustar o parar).
